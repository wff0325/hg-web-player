# 自动更新 / 预约下一季 使用说明

## 一、前端自动更新（不用再手动清缓存）

**原理**：后端每次返回首页时，会把 `app.js` / `app.css` 引用里的 `?v=...`
替换成这两个文件的**内容哈希**。文件一改哈希就变，URL 就变，浏览器/CDN
自动重新下载，不需要手动清缓存。

**你这边要做的**：改完 `web/` 下的文件，传到服务器即可。用户重新打开页面
就是新版。正在播放的用户，页面会定时（默认 30 分钟）检测到新版，顶部弹
「发现新版本」横幅，点「立即刷新」即可。

**相关配置**（`web/config.js`）：
- `AUTO_UPDATE: true` —— 开关，设为 `false` 完全关闭检测
- `UPDATE_CHECK_MS: 1800000` —— 检测间隔，单位毫秒（默认 30 分钟）

**相关接口**：`GET /version` 返回 `{ ok, version }`，version 即内容哈希（免鉴权）。
改文件后最多 8 秒哈希刷新（服务端缓存）。

**注意**：
- 哈希只算 `app.js` 和 `app.css`。如果改了 `index.html` 结构或 `config.js`，
  用户刷新页面本身就会拿到新的 HTML，但 app.js/app.css 若不改则仍走缓存——
  这种改动建议在文件末尾加个空行（让 app.css 哈希变化）强制刷一次。
- 表情 SVG（`assets/emoji3d/`）不在哈希范围内，改表情后需用户强刷一次。

## 二、预约下一季

**入口**（两处）：
1. 详情页按钮栏的「预约下一季」（与收藏并列）
2. 看完最后一集，底部提示卡里的「预约下一季」

**存储**：浏览器 localStorage，键 `mr.reservations`，结构：
```
{
  "<剧ID>": { title, base, num, at, notifiedNum }
}
```
- `base`：去掉季号的剧名；`num`：预约时的季号；`notifiedNum`：已提醒过的季号
- 没有账号体系，**只在本机生效，换设备不同步**

**逻辑**：预约后，页面启动时检查已预约的剧是否上线了季号更大的新季
（用 `/search` + 季号解析，与"找下一季"共用一套解析）。命中则顶部弹提醒，
点「去看看」直接进新季详情页。同一季只提醒一次（记 `notifiedNum`）。
为避免每次开页面都打上游，检查有 30 分钟节流（`mr.reserveCheckAt`）。

## 三、部署到线上要传的文件

本次改动涉及：
- 后端：`server/src/server.js`、`server/src/service/res.js`
- 前端：`web/index.html`、`web/assets/app.js`、`web/assets/app.css`、`web/config.js`

传完重启 Node 服务即可。前端不用清缓存（自动更新会处理）。

## 五、在线更新（GitHub 作为源）★ 新增

**仓库**：https://github.com/wff0325/hg-web-player （公开）

**工作方式**：
- GitHub 仓库存前端文件（index.html / app.js / app.css），由 `manifest.json` 列出要同步的文件。
- `config.js` **不上传**（公开仓库里是空密钥模板），真实密钥只在服务器本地，更新时不会被覆盖。
- 顶栏「检查更新」按钮 → 前端 POST `/sync-web` → 后端从 GitHub Contents API 拉取 manifest 里的文件覆盖本地 → 刷新生效。
- **全程手动**：没有自动弹窗、没有定时轮询。

**以后更新流程**：
1. 改本地 `web/index.html`、`assets/app.js`、`assets/app.css`。
2. 推到 GitHub 仓库 main 分支（覆盖对应文件，按需更新 manifest.json 的 version）。
3. 在播放器页面点顶栏的「检查更新」按钮，等提示成功后自动刷新。
4. AdKyNet 上无需手动传前端文件。

**后端依赖**：
- 模块 `server/src/service/web-sync.js`（拉取 + 原子覆盖 + 敏感文件黑名单）。
- 路由 `POST /sync-web`，用 api_key 鉴权（前端已有）。
- 配置（可选，config.json 的 `web` 段或环境变量）：
  - `HG_WEB_SYNC_REPO` / `web.sync.repo`：仓库，默认 `wff0325/hg-web-player`
  - `HG_WEB_SYNC_BRANCH` / `web.sync.branch`：分支，默认 `main`
  - `HG_WEB_SYNC_TOKEN` / `web.sync.token`：私有仓库才需要 token；公开仓库留空

**安全**：manifest 里的路径经过白名单校验，`config.js`/`apikeys.json` 永远不会被覆盖；
文件先全部下载校验通过再逐个原子替换，不会出现半更新。

**验证闭环**：故意改坏本地 app.js → 调 /sync-web → 哈希恢复为 GitHub 版本 ✓

## 六、全量在线更新（前端 + 后端）+ 版本号（v1.0）★ 最新

**仓库结构**（`wff0325/hg-web-player`，现 193 个文件）：
- `web/...` —— 全部前端（index.html、app.js、app.css、两套 emoji 共 76 个 SVG…）
- `server/src/...` —— 全部后端代码
- `version.json` —— 语义版本号
- 敏感排除：`web/config.js` 在公开仓库里是空密钥模板，`server/config/`（apikeys 等）不入仓库

**全量同步怎么工作**（`server/src/service/web-sync.js` 已重写）：
1. Git Trees API 一次递归列出仓库所有文件（新增/删除文件自动识别，不用改清单）。
2. 按最新 commit sha 从 raw 拉每个文件（sha 固定，绕开 CDN 缓存）。
3. `web/` 开头的落到本地 `web/`，`server/` 开头的落到本地 `server/`。
4. 全部下载校验通过再原子覆盖；删除「上次同步过、这次仓库已无」的旧文件。
5. **保护名单**（DENY）：`config.js`、`server/config/*`、`.sync-manifest.json` 等永不覆盖/删除——
   真实密钥安全。

**后端更新的特别说明**：Node 进程不会热加载，所以后端文件更新后**必须重启服务**才生效。
点更新时若检测到后端文件变化，会提示「后端已更新，请重启服务后生效」，前端则自动刷新。

**版本号**（`version.json`）：
- 顶栏显示语义版本（当前 **v1.0**），不再是哈希。
- 想改版本号：改仓库根 `version.json` 的 `version` 字段（如 v1.1），推 GitHub，点更新即可同步显示。
- `/version` 同时返回 `version`（内容哈希，缓存失效用）和 `display`（v1.0，显示用）。

**更新流程（最终版）**：
1. 改代码（前端在 web/，后端在 server/src/）。
2. 有实质更新就改 `version.json` 版本号。
3. 全部推到 GitHub main。
4. 播放器点顶栏「检查更新」→ 前端自动刷新 / 后端提示重启。

**验证**：改坏前端 app.js + 后端 sm3.js → 点更新 → 两者 SHA256 都恢复；
`restart=true` 正确返回；config.js 真实密钥未动；顶栏显示 v1.0；e2e_ui 18/18、e2e_season 2/2。
